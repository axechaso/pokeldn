# Switch 版《火红／叶绿》游戏汉化实现方案

日期：2026-10-17；实现状态更新：2026-10-20。目标已确认：通过 PokeLDN 为零售 Switch 版《火红／叶绿》加载游戏内简体中文。状态：已实现离线核心、ARM 页载荷、持续 Mystery Gift 协议适配、现有 PokeLDN 主机接入和无需预先提供 ROM 的只读采集。客户端实机 4 KiB 采集及正常断开已通过，但后续较长采集持续失败，已停止要求用户反复采集。固定反编译源码的中文开场原型已在 mGBA 运行，用户也已在 NS 神秘礼物窗口确认“你好！”正常显示。下一项通过 784 字节 RAM 挂钩测试真新镇一处 NPC 的中文首句，等待 NS 正常剧情画面验收；没有绕过 ROM 写入门禁，通用编码、完整剧情和零售机 ROM 加载仍未交付。入口与证据范围见[汉化运行时补丁工具](frlg_localization.md)。

**建议采用“运行时 ROM 差分加载”路线。先复现单页写入，再在零售机验证，随后完成一处中文对话，最后扩展完整汉化并封装插件。** 完整关闭游戏后重新加载作为第一版的使用方式；永久安装不列为首版前提。

## 1. 已知能力与真正的缺口

| 项目 | 当前证据 | 对方案的含义 |
| --- | --- | --- |
| Console Code 与客体内存操作 | PokeLDN 已有相关构建器、读取工具与会话代码 | 复用入口、识别和回读能力 |
| 运行时 ROM 写入与执行 | 上游在修改版 Ryubing 中完成实验 | 可以据此设计原型，仍需本地复现 |
| 软复位与完整重启 | 上述实验中，ROM 改动跨软复位保留，完整重启后恢复 | 分别测试字节保留、渲染状态和重新加载 |
| 同一路径在零售 Switch 上写 ROM | 上游这项记录明确未验证零售机 | 必须作为扩大开发投入前的关口 |
| 中文文本引擎和大容量资源加载 | 本项目未实现 | 需要独立开发，插件框架不能代替 |

上游实验依据固定为 [ROM 写入实验](https://github.com/Decryptu/pokeldn/blob/da882c7633ff106a0d2206fa2015a3538777e542/docs/frlg_rom.md#the-flash-sector-path)。修改版模拟器中的结果不能自动推定为原版模拟器或零售机结果；复现记录必须写明模拟器改动是否只用于观察，还是改变了被测行为。

本地代码还有两个具体约束：

- `build_flash_write()` 只接受存档 Flash 的 0–31 号扇区。
- 通用 `sloop-svc` 构建器明确拒绝 `swi 0x48/0x56`，不是加一个 `--write-unsafe` 就能使用。

因此新增**专用 ROM 页写入器**，独立校验 ROM 目标和暂存源，保留现有存档工具的限制。[本地构建器](../pokeldn/frlg/rom/buffer_script.py)

## 2. 第一版的范围

首个面向用户的构建优先选择英文《火红》BPRE、客体 ROM 修订号 0x0A；这是开发默认值，实际执行前必须匹配主机上的游戏。上游实验复现应先使用其原始构建和环境，再迁移到目标版本。

首版应做到：

1. 识别游戏构建，拒绝未知版本。
2. 加载小规模中文差分，结束通信后在游戏中显示。
3. 正常关闭对话、切换地图、进入战斗和返回标题。
4. 可恢复原文；完整重开游戏后可以重新加载。
5. 在记录的具体零售主机、游戏版本和无线设备组合上复现。

**第一个可展示成果：一处固定对话、约 20–50 个汉字，玩家名、换行、换页和等待操作正确。** 完整剧情、菜单、战斗消息、图鉴和图片文字分批扩展。

叶绿、法文、日文各自建立版本配置和验收记录。玩家名、宝可梦昵称、存档字段及联机数据第一版保持原编码；展示汉化不应改变它们的格式。

## 4. 整体架构

```text

                ↓
     文本解析、编码、排版和差分构建
                ↓
     带版本指纹和逐页校验的补丁包

                ↓
```

## 5. 版本识别和补丁格式

不能只用“火红”或 `BPRE` 判断兼容。每份版本配置至少记录：

- 游戏代码、客体 ROM 修订号、原始 ROM 大小和 SHA-256。
- Switch 标题及更新版本、包装器构建身份；无法可靠识别时明确标为未知，仅允许只读检查，不进入写入阶段。
- 包装器的已知启动改动及其精确位置、预期字节。
- 字符解码、绘制、字宽和字符串处理入口的原始指令。
- 允许存放译文和字库的区间、通信保护区、暂存区及其证据。

原始文件与运行中的 ROM 要分开计算指纹。只能按已验证规则处理包装器启动改动；不能把无法解释的差异全部忽略。

补丁包的清单至少包含：

| 字段 | 内容 |
| --- | --- |
| `format_version`、`patch_id` | 格式版本、内容身份 |
| `profile_id`、`base_sha256` | 唯一目标构建 |
| `pages[]` | 页偏移、原始/目标 SHA-256、差分数据和种类 |
| `activation` | 入口页、依赖页和启用顺序 |
| `resources` | 字库版本、字形数量、文本覆盖范围 |
| `compatibility` | 已验证宿主版本、设备组合和重启行为 |

补丁包通过完整校验之后才能开始会话。完整 ROM、运行密钥和个人存档不进入插件包；本机的完整原始页用于恢复。

## 6. 4 KiB 页上传与恢复

上游研究的写入单位是 4 KiB。现有 buffer script 的单次接收尺寸不能直接容纳整页，因此需要验证“多个接收/运行步骤 → 一次提交 → 回读”的会话组织。

暂存布局至少包含 4 KiB 数据、块接收状态及提交代码。三者必须与接收缓冲、通信对象、当前脚本和其他常驻代码互不重叠。地址来自构建配置；不能把示例地址直接当作通用空闲空间。

每页流程：

1. **读取与预检**：读取完整原始页，检查其指纹、允许改动范围和当前代码执行位置。
2. **合并**：在主机生成完整目标页，保持同页未修改字节及包装器启动改动。
3. **暂存**：分块传送；块大小扣除头部与脚本开销，不将 1,024 字节接收上限视为净数据容量。
4. **完整性检查**：全部块到齐，核对偏移、长度、重复块和暂存内容；未通过时不提交。
5. **提交**：专用构建器只生成允许的 ROM 目标和写入路径。
6. **回读**：回读完整页，在主机计算 SHA-256，并比较目标字节。
7. **激活**：所有资源与代码页通过回读后才切换渲染入口；激活时重新核对原始指令和执行位置。

会话消息携带 `session_id`、补丁 ID、页号、块偏移、长度和校验值。相同内容重复发送可以接受；相同位置出现不同内容必须失败。

建议的主机状态：

```text
IDENTIFIED → PREPARED → STAGING → WRITTEN → VERIFIED
                                      ↓
                         所有依赖页通过 → ACTIVATED → COMPLETE
任一步失败 → STOPPED → 按日志恢复 / 经过验证的完整重启恢复
```

`session_id` 只用于关联一次传输，不能用来证明游戏进程没有重启。恢复或重连时必须重新识别并回读受影响页；当前页既不匹配原始值也不匹配目标值时停止。

整个多页补丁不承诺原子提交。恢复按依赖逆序进行：先撤销入口，再恢复资源和代码页；必须记录每页写入状态、原始指纹和是否激活。若补丁影响通信路径，应在规划阶段拒绝该布局，而不是依赖断线后继续回滚。

研究写入器限定为 `swi 0x48` 对应路径；`swi 0x56` 存在额外修改页内字节的行为。普通 Flash 工具不扩大参数范围来兼任此功能。[路径差异](https://github.com/Decryptu/pokeldn/blob/da882c7633ff106a0d2206fa2015a3538777e542/docs/frlg_rom.md#the-flash-sector-path)

## 7. 中文编码、字库与渲染

采用“Unicode 译文 → 文本及控制符中间表示 → 专用编码”的离线管线。先确定可用编码空间，再选定扩展方案，不能凭空指定一个前缀字节就开始翻译。

现有国际版定义包括 `0xFA/0xFB` 提示操作、`0xFC` 扩展控制、`0xFD` 变量、`0xFE` 换行和 `0xFF` 结束标记；其参数必须按命令解析。未知命令原样保留并阻止未经复核的改写。[字符与控制符定义](../pokeldn/frlg/text/charmap.py)

中文实现需要一起验证：

- 解码及字形索引；原有英文和符号回退。
- 字符推进、字宽、换行及文字滚动。
- 字符串复制、长度计算、截断和变量展开。
- 普通对话、菜单和战斗消息各自使用的文字路径。
- 软复位后的入口、缓存和 RAM 状态初始化。

不能只替换字库，也不能仅修改绘制函数却让复制/截断函数切断多字节字符。第一轮仅接入已覆盖完整处理链的一种对话窗口。

对中文采用像素宽度验收：离线构建时检查窗口宽度和分页；对玩家名等动态值使用字段允许的最长有效值测试。场景包含中英文混排、数字、标点和最长变量展开。

字库按实际译文生成子集，字体源需具备适当的分发许可。举例：3,000 个 16×16、2bpp 字模仅像素数据就需要 192,000 字节，另有索引、字宽与代码。现有约 1 KiB 常驻区无法承载整套资源，资源必须放在已证实可用的 ROM 范围内。

### 7.1 当前剧情原型的字体参数

剧情原型把字体选择和渲染参数固定在可复现的离线步骤中，避免在游戏运行时下载或重排字体：

| 项目 | 当前值 |
| --- | --- |
| 字体源 | Noto Sans CJK SC Regular，固定提交 `f8d157532fbfaeda587e826d4cd5b21a49186f7c`，SHA-256 `2c76254f6fc379fddfce0a7e84fb5385bb135d3e399294f6eeb6680d0365b74b`，OFL-1.1 |
| 离线栅格 | Pillow 12.3.0，13 px，16×16 单元，baseline 13，`stroke_width=0`，2bpp 行序位图 |
| 游戏转换 | 只为 `科学的力量真伟大！` 的 9 个字形生成 1bpp 常驻数据；2bpp 级别 1、2、3 都保留为墨色，代码常量为 `GLYPH_INK_THRESHOLD = 1` |
| 游戏排版 | 原生窗口仍按固定 14 px 推进、16 px 高；字体 JSON 的离线 `advance` 不改变这条已验证的游戏路径 |
| 常驻占用 | 9 × 32 B = 288 B；整个剧情载荷仍限制在 1 KiB RAM 槽内 |
| 缺字策略 | 离线构建遇到缺字即失败；英文、数字和符号继续走原版字体回退，不在运行时静默替换 |

选择 13 px 是为了给 16 px 单元留出稳定的上下边距；保留最低一级 2bpp 墨色则避免 GBA 原生缩放时细横画消失。候选字体必须通过同一 mGBA 帧缓冲脚本，确认中文首句、英文续页、按键清页和软复位后的恢复行为，再更新提交的位图资源。

原型阶段先使用少量自编译文。已有 GBA 汉化资源只有在核对许可、源版本、编码、指针、扩容需求和代码差异后才考虑迁移；其他 GBA 修订的汉化 ROM 不直接覆盖 Switch 的 ROM 副本。

## 8. 阶段、验收与停止条件

| 阶段 | 实施内容 | 交付和放行条件 |
| --- | --- | --- |
| P0：固定环境 | 识别构建、整理地址证据、无修改往返、保护区检查 | 版本配置、基线报告、离线检查；未知构建拒绝 |
| P1：模拟器单页 | 同构建复现写入、回读、恢复和取指；验证模拟器改动性质 | 页面及邻页核对通过，重试和中断可诊断 |
| P2：零售机写入 | 同一主机工具与受约束载荷，小范围验证、回读、恢复 | 真实主机证据齐全，无需调试器代写；通过后扩大投入 |
| P3：最小中文 | 一处对话、20–50 汉字及变量和分页 | 模拟器与已验证零售机均能显示，退出及恢复原文正常 |
| P4：扩大内容 | 菜单 → 战斗消息 → 剧情 → 图鉴 → 图片文字 | 每批覆盖报告、功能回归和人工游戏测试通过 |
| P5：插件交付 | 文件选择、版本门禁、进度、恢复、兼容提示 | 完整安装与使用流程可复现，发布指定构建的试用版 |

P1 应分别验证数据读取和代码取指，排除只改了数据镜像、执行端仍使用旧代码的情况。P2 在通过页写入实验后，也需验证计划中的渲染代码执行方式。

P2 所需硬件暂时不可用或实机传输尚未稳定时，可以并行做 P3 的有限模拟器原型，但不把它作为零售版阶段已经完成的依据。

当前按此路径推进：先以 `pret/pokefirered` 固定提交 `037335f4c725d7c9aecdac87066f2002b4bd7e14`
的 `compare_firered_switch` 目标建立英文修订版 10 基线，再从文字绘制、字宽、字符串复制及控制符源码
开发一处中文对话。完成模拟器中的显示、退出和恢复后，才安排有明确验收目标的小范围实机验证。
开发阶段的代码取证优先由开发环境完成，不将长时间无线 ROM 采集作为普通用户的前置操作。

任何一项出现以下情况，暂停扩大补丁范围：

- 写入成功依赖改变模拟器业务行为或直接从调试器代写内存。
- 页回读、邻页比对或恢复失败。
- 暂存区被游戏覆盖，或目标页与通信/正在执行的代码重叠。
- 无法定位足够资源空间，或编码修改破坏原有字符串处理。
- 版本、启动补丁或入口指令存在无法解释的差异。

首个研究窗口建议为 1–2 周，以 P0–P2 的可复现结果或明确失败原因作为交付。P3 再安排小规模渲染验证；P2 通过之前不承诺完整零售汉化的发布日期。完整文本、校对和通关测试另行估量。

## 9. 测试、存档和重启行为

离线测试：编码往返、未知控制符、变量、缺字、窗口溢出、页合并、保护区、指纹不匹配，以及丢包、乱序、重复包、旧会话数据和回读不一致。

每个已支持构建分别记录：

| 场景 | 核对内容 |
| --- | --- |
| 加载与重复加载 | 目标页一致、没有重复安装入口 |
| 对话/地图/菜单/战斗 | 字体和变量正确、正常返回、原有输入流程正常 |
| 返回标题 | 页面和入口状态是否仍有效 |
| 软复位 | ROM 字节、入口和 RAM 初始化分别检查 |
| 完整关闭并重启 | 还原范围、是否需要重新加载、原存档可继续 |
| 主机中断/USB 断开 | 写入阶段可判定，没有把部分成功显示为全部成功 |
| 手动恢复 | 先撤入口再恢复各页，最终原始指纹一致 |

Mystery Gift 成功会话可能触发游戏保存，因此仅针对 ROM 的补丁也要把会话保存行为计入测试。测试前保留恢复材料，之后核对关键存档语义；预期的保存计数变化与异常字段变化分开判断。

第一版不把汉化资源写入存档填充区，也不占用正在使用的 Resident/RNG 区域。小型保存加载器不能自动提供完整字库和译文的持久化；完整重启后的免连接自动恢复单独立项。

每次实验输出游戏构建、PokeLDN/模拟器/固件版本、补丁 ID、页哈希、耗时、状态日志及画面证据。加载速度按整条链路实测，包含命令、提交和回读耗时。

## 10. 第一批可直接拆分的开发任务

| 顺序 | 任务 | 完成标志 |
| --- | --- | --- |
| 1 | 建立独立检出和环境锁定记录 | 现有远程交换与 RNG 工作不混入；基线可重建 |
| 2 | 实现版本配置及纯离线补丁校验 | 错版本、改动保护区和错误页指纹能够被拒绝 |
| 3 | 实现完整页合并与恢复日志 | 未修改字节保持一致，可由日志重建原始页 |
| 4 | 实现暂存、专用提交构建器和模拟器会话 | 一页上传、回读、恢复闭环通过 |
| 5 | 执行零售机单页验证 | 提供独立实机记录，决定是否进入中文渲染 |
| 6 | 开发最小编码与渲染链 | 指定对话在目标设备显示中文并恢复原文 |

第一批暂不铺开完整译文、全字库、多语言版本和插件自动更新。它的成果是明确回答“能否在目标零售构建上可靠加载汉化所需改动”。

后续核心稳定后，插件界面提供补丁检查、加载、当前状态、恢复及实验记录导出。使用上游插件的进度和状态展示接口，最低 API 版本按实际使用项声明；自定义页上传仍由固定版本的主机适配器实现。[插件接口](https://github.com/Decryptu/pokeldn/blob/da882c7633ff106a0d2206fa2015a3538777e542/docs/plugins.md)

形成大改后，按项目约定运行相关检查、提交并推送功能分支、创建 PR，触发 GitHub Actions。发布产物包括加载器、版本专用差分、可分发字体和译文、校验值、兼容矩阵及恢复说明；以已验证范围描述能力。
